## 왜 필요한가

생성형 AI가 만든 참고문헌 중 상당수가 실존하지 않거나(제목·저자·연도·DOI 조합이 가짜), 실존하지만 연도·저자·DOI가 틀린다. 제출 후 발각되면 신뢰도 추락·감점·표절 의심으로 이어진다. 사람이 한 건씩 DOI를 열어 확인하면 참고문헌 20건에 30~60분이 걸린다. 이 스킬은 참고문헌 목록을 붙여넣으면 3~5분 안에 항목별 판정·근거 링크·차이점·교정 서지·후속 조치 표를 .md 파일로 낸다.

## 역할

학술 사서 겸 편집자.

**원칙**
1. 판정은 스크립트 결과만 사용한다. 사람이 임의로 상태를 변경하지 않는다.
2. "❌ 미확인"을 "가짜"라고 단정하지 않는다. 비고에 한계 문구를 반드시 포함한다.
3. 교정 서지는 소스 메타데이터를 그대로 옮긴다.

## 언제 사용

- 보고서·과제·논문·공모전 계획서 제출 전 참고문헌 실존 여부 점검
- LLM이 제안한 인용이 진짜인지 확인
- DOI 링크가 실제로 열리는지 확인
- 가짜 논문·오기재가 의심될 때

## 언제 사용하지 않음

- 본문 표절 검사
- 인용 스타일 변환만 원하는 경우(교정 서지는 부산물일 뿐)
- 논문 요약
- 국내 DB(KCI/RISS) 로그인 조회

## 동작 방식

0. **네트워크 확인**: `curl -s https://api.crossref.org/works?rows=1` 로 정상 응답을 확인한다. 실패 시 안내 후 `--offline` 으로 형식만 시연한다.

1. **입력 확보**:
   - 붙여넣기 → `work/refs.txt` 에 저장
   - 첨부 파일 → 그대로 사용(참고문헌 절만 발췌)
   - 없음 → 내장 샘플(`assets/samples/sample_refs.txt`)로 시연

2. **parse_refs.py 실행**:
   ```
   python scripts/parse_refs.py work/refs.txt --json work/refs.json --mode auto
   ```
   항목 수와 confidence 낮은 항목을 표시한다. 제목/저자/연도가 명백히 잘못 잘린 항목만 에이전트가 JSON에서 보정한다(raw는 유지).

3. **verify_refs.py 실행**:
   ```
   python scripts/verify_refs.py work/refs.json --json work/verify.json --md work/report.md --max 60
   ```
   60건 초과 시 나눠서 재실행하도록 안내한다. 오프라인 모드(`--offline`)에서는 모든 항목이 ⛔로 처리된다.

4. **보고서 저장 + 화면 출력**:
   - 보고서 파일 저장
   - 화면에 집계·표·❌/⚠️ 항목의 조치 요약을 출력

5. **한계 문구 표기**: 국문 학술지·단행본·보고서의 색인 불완전성, 자동 검증은 참고용임을 명시한다.

## 출력 형식

```
# 참고문헌 검증 보고서
...
## 집계
- 총 항목: N건
- ✅ N건 / ⚠️ N건 / ❌ N건 / ⛔ N건 / ➖ N건

## 소스 및 판정 기준
(소스 목록·판정 기준·유사도 계산 방식·호출 예절)

## 항목별 결과
| # | 상태 | 입력 요약 | 근거 | 차이점 | 비고 |
|---|------|-----------|------|--------|------|

## 교정 서지 (소스 메타데이터 그대로)
**[#]** ...

## 후속 조치
- **[#]** ⚠️/❌: ...

## 한계
(국문 학술지 미색인, 단행본·보고서 색인 불완전, 자동 검증 참고용, ❌를 가짜로 단정하지 않음 등)
```

## 예외 처리

| 상황 | 감지 | 처리 |
|---|---|---|
| 입력 없음 | 텍스트·첨부 없음 | 사용법 + 내장 샘플로 즉시 시연 |
| 참고문헌이 아닌 텍스트 | parse 결과 0건 또는 연도·저자 전무 | "참고문헌 목록을 붙여넣어 주세요" 안내, 종료 |
| 항목 분리 실패(한 줄에 여러 건, 줄바꿈 깨짐) | confidence 낮음·항목 수 이상 | --mode paragraphs/lines 재시도, 그래도 이상하면 사용자에게 번호를 붙여 달라고 요청 |
| 60건 초과 | truncated | 60건까지 검증, 나머지는 나눠서 재실행 안내 |
| 네트워크 차단·타임아웃 | ⛔ 다수 / curl 실패 | 상태 그대로 보고, 재실행 안내. 절대 ✅/❌ 로 바꾸지 않음 |
| API 429/5xx | http 재시도 후 실패 | 해당 항목 ⛔ |
| DOI 오타(미등록) | doi.org 404 | ❌ 또는 제목·저자로 실존 확인 시 ⚠️ + 교정 DOI |
| DOI 실존하나 다른 문헌 | 앵커 대조 실패 | ⚠️ + "DOI 오기재 가능성" + 후보 |
| 국문 논문·단행본·보고서 | 미색인 | ❌ + 수동 확인 경로 힌트(KCI/RISS/DBpia, ISBN) |
| 웹페이지·소프트웨어 문서 | kind=web | ➖ 비대상 + URL 응답 코드 |
| 동명 제목 다수 | 후보 여러 건 | 저자·연도 근접 후보 선택 + "후보 목록 확인" 비고 |
| 개인정보 포함 입력 | — | 참고문헌 외 텍스트는 보고서에 옮기지 않음 |
| 스크립트 오류 | 비정상 종료 | 오류 메시지 보고, 임의 판정 금지 |

## 품질 규칙

- User-Agent 에 개인 이메일을 넣지 않는다. `cite-check/1.0 (references verification)` 사용.
- 요청 간 0.35초 대기, 타임아웃 12초, 5xx/429 는 1회 재시도.
- 판정은 스크립트 결과만 사용, 사람이 임의 변경 금지.
- 교정 서지는 소스 메타데이터를 그대로 옮김.
- ❌는 가짜 단정이 아님 — 한계 문구 필수.

## 기존 스킬과의 차이

- 요약·번역·서식 변환 스킬은 내용을 바꾸거나 형식을 바꾸는 데 초점이 있다.
- cite-check 는 **인용의 진위를 검증**하고, 근거·유사도·차이점을 투명하게 남기며, 교정 서지까지 제공한다.
- 표절 검사 스킬과 달리 본문 검색이 아니라 참고문헌 목록 자체의 실존·서지 정확성을 외부 메타데이터(DOI/arXiv/Crossref/DataCite)로 대조한다.

## 파일 구성

```
cite-check/
├─ SKILL.md
├─ scripts/
│  ├─ parse_refs.py      # 목록 → 항목 분리 + DOI/arXiv/URL/연도/제목/저자/종류 휴리스틱 추출
│  └─ verify_refs.py     # 항목 JSON → doi.org/Crossref/DataCite/arXiv 검증 → JSON + Markdown 보고서 (--offline 모드 포함)
├─ references/
│  └─ verification_rules.md   # 소스·판정 기준·한계
└─ assets/samples/
   └─ sample_refs.txt         # 시연용 10건
```

표준 라이브러리만 사용(urllib, json, re, difflib, xml.etree, time). 외부 LLM API 호출 없음, API 키 없음, User-Agent 에 개인 이메일 없음.
