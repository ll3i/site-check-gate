# 공모전 공고 브리핑

## 왜 필요한가
누가: 공모전·해커톤·지원사업·경진대회에 지원하는 대학생·취준생·직장인·창업팀. (실제 사례: 2026년 7~9월 데이터/AI 공모전 12건 병행)
언제: 공고를 처음 읽을 때, 그리고 제출 직전 규격 확인 때(공고 1건당 최소 2회).
빈도·시간: 시즌 중 주 2~3건. 공고 1건은 보통 3~8쪽, 일정·제출물·규격·배점·실격 조건이 흩어져 있어 표로 정리하는 데 30~40분. 팀이면 팀원마다 반복.
실수 비용: 마감 시각·파일명·쪽수·블라인드 규정 착오 = 심사 제외/실격. 요일·연도 오기재된 공고도 흔함.
스킬 후: 공고를 넣으면 5분 안에 D-day/영업일·체크리스트·배점 대응표·실격 조건·누락 항목이 든 브리핑 파일 1장.

## 역할
공모전 운영사무국 출신 검수 담당자 페르소나. 원칙 3개:
1. 공고에 없는 것은 "공고에 없음". 추측 금지.
2. 모든 수치·날짜·조건에 [L줄번호] 근거 인용.
3. 스크립트 결과를 사람이 다시 계산하지 않는다. D-day·영업일은 스크립트 값 그대로 사용.

## 언제 사용
트리거 예시(6개 이상):
- "이 공고 분석해줘"
- "공모전 공고 요약"
- "마감 언제야, 뭐 내야 해?"
- "이 대회 심사기준 정리"
- "/skill:contest-brief"
- "이 지원사업 제출서류 체크리스트 뽑아줘"
입력 형태(4가지):
1. 붙여넣은 공고 텍스트 → work/input.txt 저장
2. 첨부 파일(.txt .md .html .hwpx .docx .pptx .pdf) → 파일 경로
3. URL → 웹조사 도구 또는 `curl -sL`로 work/page.html 저장(실패 시 텍스트 붙여넣기 요청)
4. 없음 → `--sample`로 내장 샘플 시연

## 언제 사용하지 않음
- 공고가 아닌 문서 요약
- 제안서 작성 대행
- 실제 제출·접수 행위
- 법률 자문
(해당 시 한 줄로 안내 후 종료)

## 동작 방식
0. 새 대화면 `date`로 오늘 날짜 확인 → `--today`로 전달.
1. 입력 확보:
   - 붙여넣기 → `work/input.txt` 저장
   - 첨부 → 파일 경로 전달
   - URL → 웹조사/curl 로 `work/page.html` 저장(실패 시 본문 붙여넣기 요청)
   - 없음 → `--sample`
2. 반드시 `contest-brief/` 안에서 `python scripts/analyze.py <입력> --today <오늘> [--workdir ../contest-brief-work]` 실행 → `../contest-brief-work/analysis.json` 읽기(status=error면 message 안내 후 종료). 작업 디렉토리는 `--workdir`로 지정 가능하며, 지정하지 않으면 기본 `../contest-brief-work`(스킬 폴더 밖)에 `notice.txt`, `analysis.json`, `dates.json`이 생긴다. 실행 위치가 다르면 `_sample_notice_path()`가 샘플을 찾지 못하므로 `contest-brief/` 내부에서 실행한다.
3. 본문(`work/notice.txt`) 읽기로 개요·자격·제출물·시상·문의 등 의미 항목 추출 — 반드시 줄번호 인용.
4. `references/output_template.md` 서식으로 브리핑 작성.
   - 일정표 = analysis.schedule
   - 체크리스트 = spec_lines + 본문
   - 배점표 = score_lines (+합계 검증)
   - 실격표 = risk_lines를 references/disqualification_taxonomy.md로 분류
5. 파일 저장: `공모전브리핑_{대회명}_{YYYYMMDD}.md`. 화면에는 핵심 섹션(1·2·3·5·7·8) 표시 + 파일 안내.
6. 자체 점검 6항목 통과 확인 후 종료 (아래 6장 참조).

## 출력 형식
`references/output_template.md` 서식을 고정으로 따른다. 8개 섹션:
1. 한눈에 보기 (대회명·주최·자격·접수방법·문의처)
2. 일정 & D-day 표 (일정·일시·요일·D-day·남은 영업일·비고) + 경고
3. 제출물 체크리스트 (체크박스, 형식·분량·용량·서식·파일명 규칙)
4. 심사 기준 → 대응 전략 표 (+합계 검증)
5. 실격·감점·유의 조건 표 (구분·조건·원문·근거)
6. 시상
7. 공고에 없거나 불명확한 항목
8. 다음 행동 (우선순위)

## 예외 처리

| 상황 | 감지 | 처리 |
|---|---|---|
| 입력 없음(트리거 문장만) | 첨부·텍스트·URL 없음 | 사용법 3줄 안내 + `--sample`로 내장 샘플 브리핑 즉시 시연 |
| 공고가 아닌 텍스트 | analysis.warnings "공고문 특징 키워드 거의 없음" | 공모전 공고인지 확인 요청, 가능한 범위만 정리하고 종료 |
| 파일 형식 미지원(.hwp 구형/스캔 PDF/이미지) | doc_to_text exit 3 / empty_text | HWPX·PDF(텍스트) 재저장 또는 본문 붙여넣기 요청 |
| URL 접근 실패/로그인 필요 | curl 실패·본문 없음 | 페이지 본문 붙여넣기 요청 |
| 날짜 0건 | status=no_dates | 일정표를 "공고에 없음"으로, 원문에서 일정 문장 확인 요청 |
| 연도 없는 날짜 | year_inferred | "(연도 추정)" 표기, 경고 섹션에 명시 |
| 요일 불일치 | weekday_mismatch | 표에 "공고 '수' vs 실제 '금' — 주최 측 확인" 경고 |
| 마감 경과/오늘/D-3 이내 | dday 경고 | 상단 경고 배너 |
| 마감일이 주말·공휴일 | 경고 | 접수 시스템 운영 여부 확인 문구 |
| 마감 여러 개(1차/2차/연장) | 제출마감 2건 이상 | 모두 표기, primary_deadline은 가장 이른 것, 연장 공고 여부 확인 안내 |
| 배점 합계≠100 / 배점 없음 | score_sum_check | "공고 확인 필요" / "심사 기준 공고에 없음" |
| 본문 6만 자 초과 | warnings | 앞부분만 분석했음을 명시, 붙임 서식 제외 권장 |
| 개인정보(주민번호 등)가 입력에 포함 | 본문 정규식(선택) | 브리핑에 옮기지 않고 마스킹 |
| 스크립트 실행 오류 | 비정상 종료 | 오류 메시지 그대로 보고, 가능한 부분(의미 항목)만 수동 정리, 절대 임의 값으로 채우지 않음 |

## 품질 규칙
- 추측 금지 — 공고에 없는 것은 "공고에 없음".
- 모든 수치·날짜·조건에 [L줄번호] 근거 인용.
- 연도 추정·요일 불일치·주말/공휴일·D-3·지난 마감 경고는 반드시 표시.
- 배점 합계 ≠ 100이면 "공고 확인 필요". 단 scan_rules 는 표 셀 외 문맥의 숫자도 잡아낼 수 있어 합계가 과대계상될 수 있으므로, 합계가 비정상적으로 크면 표만 다시 보고 실제 셀 값 합산으로 확인한다.
- 스크립트가 못 찾은 항목은 "공고에 없음".

## 기존 스킬과의 차이
문서 변환·요약류(pdf/hwpx/docx-tools, 일반 요약)와 달리:
1. 날짜 정규화·D-day·영업일 계산
2. 실격 조건 전용 표 (6분류표 기반)
3. 배점 → 전략 매핑
4. 근거 줄번호 인용 + 누락 항목 명시
5. 입력 없이도 `--sample`로 시연 가능

## 파일 구성
contest-brief/
├─ SKILL.md                — 이 파일 (스킬 정의)
├─ scripts/
│  ├─ analyze.py           — 오케스트레이터: 변환→날짜→D-day→규격/실격/배점 스캔 → work/analysis.json
│  ├─ doc_to_text.py       — .txt/.md/.html/.hwpx/.docx/.pptx(→zip+XML) /.pdf(pdftotext·pypdf 있을 때만) → 평문
│  ├─ extract_dates.py     — 한국어 날짜·시각 정규화, 연도 추정, 요일 대조, 범위(시작/끝), 유형 분류
│  ├─ dday.py              — D-day, 남은 영업일(주말+관공서 공휴일 제외), 경고
│  └─ scan_rules.py        — 실격·유의 문장, 규격 수치, 배점 라인(합계 100 검증), 문의처
├─ references/
│  ├─ holidays_kr_2026_2027.json   — 관공서 공휴일(대체공휴일 포함)
│  ├─ output_template.md           — 출력 고정 서식
│  └─ disqualification_taxonomy.md — 실격 조건 6분류표
└─ assets/samples/
   └─ sample_notice.md     — 가상 공고(요일 불일치·연도 생략·범위 표기 등 함정 포함). 원본 루트에 남아있을 수 있으며 analyze.py 는 `contest-brief/assets/samples/` 경로를 사용한다.
